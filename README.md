# Mini Collector 
![image](https://img.shields.io/badge/Go-00ADD8?style=for-the-badge&logo=go&logoColor=white)
![image](https://img.shields.io/badge/Docker%20Compose-2496ED?style=for-the-badge&logo=docker&logoColor=white)

Определение SYN-flood атаки, а также проверка IP-адресов на принадлежность к botnet-сетям.

## Цели
- Изучение gRPC и protobuf
- Приобретение навыков работы с пакетами: `context`, `netip` и `gopacket`

## Архитектура 
### Клиент
Клиент - имитация сервиса, который пересылает пришедшие к нему пакеты на сервер для анализа IP-адресов и детекции SYN-flood атаки. Клиент общается с сервером с помощью RPC-вызовов и proto-сообщений.

#### Генерация пакетов уровней TCP/IP с последующей отправкой на сервер 
Клиент раз в 10 секунд случайно генерирует `CNT_PACKETS` пакетов одного из трёх видов:
1) `type=1` - пакеты с отсутствием SYN-флагов
2) `type=2` - пакеты только с SYN-флагами
3) `type=3` - пакеты как с SYN-флагами, так и без них (генерируется равное количество пакетов).

IP-адрес изначального отправителя генерируется случайно, IP-адрес получателя задается в `.env`.

После потоковой отправки клиент ожидает результат анализа переданных пакетов от сервера. Затем клиент анализирует верно ли сервер определил наличие или отсутствие SYN-flood атаки и выводит результаты в консоль.

#### Генерация случайных IP-адресов с последующей отправкой на сервер
Помимо пакетов клиент независимо генерирует случайные IP-адреса, изменяя случайным образом определённые байты:
- для IPv4 - третий байт 
- для IPv6 - восьмой байт

Сгенерированные IP-адреса вместе с временной меткой отправляются на сервер раз в 5 секунд с помощью RPC-вызова и proto-сообщения.

Предполагается, что уже известны botnet-адреса сетей:
1) ipv4 - 192.168.0.0/24
2) ipv6 - 2001:0db8:85a3:0000::/64

IP-адреса обычных клиентов генерируются из сетей:
1) ipv4 - 142.168.0.0/20
2) ipv6 - 2001:0db8:12a3:0000::/64

#### Настраиваемые параметры

В файле `/client/.env` можно задать параметры, регулирующие работу клиента:
- `GRPC_SERVER_ADDR` - адрес `gRPC`-сервера
- `DEST_IP` - адрес получателя, который указывается при генерации IP-пакетов
- `CNT_PACKETS` - сколько пакетов требуется генерировать 

Параметры по умолчанию:
- `GRPC_SERVER_ADDR="localhost:8080"`
- `DEST_IP="132.18.96.8"`
- `CNT_PACKETS=10` 

### Сервер 
Сервер работает на порту :8080 и принимает RPC-вызовы. 

#### Обнаружение SYN-flood атаки
Сервер принимает TCP/IP пакеты и с помощью скользяющего окна (размер окна - 1 секунда) анализирует сколько SYN-флагов пришло на адрес получателя. Если количество пакетов с SYN-флагами в секунду превышает заданный порог, то сервер отправляет ответ клиенту c сообщением об обнаружении атаки. 

Формат сообщения:
- `attack_detected` - тип `bool` 
- `cnt_syn_pkg` тип `int`, количество SYN-пакетов в секунду
- `target` тип `string`, адрес атакуемого.

#### Анализ IP-адресов 
Помимо анализа пакетов на сервере выполняется проверка IP-адресов на принадлежность к botnet-сетям. В случае обнаружения адреса из botnet-сети, сервер сохраняет IP-адрес и время обнаружения в базу данных ClickHouse. 

#### Настраиваемые параметры

В файле `/server/.env` можно задать параметры, регулирующие работу сервера:
- `DB_PASSWORD` - пароль для базы данных ClickHouse. **Если не задать значение данной переменной, то проект не запустится.**
- `DB_ADDRESS` - адрес базы данных ClickHouse
- `BATCHSIZE` - так как на сервере организована пакетная вставка в ClickHouse, то можно задать размер пачки для "сброса" данных
- `FLUSH_INTERVAL` - интервал для принудительного "сброса" данных в ClickHouse, измеряется в секундах
- `COUNT_OF_PACKET_CAN_PROCESS` - сколько пакетов для обработки ожидается в одном RPC-вызове. Данный параметр позволяет эффективно выделить память при обработке пакетов
- `THRESHOLD` - допустимый порог SYN-флагов, пришедших за 1 секунду. Как только количество пакетов с SYN-флагами превысит порог, сервер отправит сообщение об обнаружении SYN-flood атаки.

Параметры по умолчанию:
- `DB_ADDRESS="db:9000"` 
- `BATCHSIZE=25` 
- `FLUSH_INTERVAL=10` 
- `COUNT_OF_PACKET_CAN_PROCESS=10` 
- `THRESHOLD=5` 

## Запуск проекта
Перед запуском проекта необходимо установить `Docker Compose` и создать `server/.env`. В файле `server/.env` требуется задать **обязательный** параметр `DB_PASSWORD`- пароль для базы данных. Остальные параметры опциональны, будут использованы значения по умолчанию. Поля должны именоваться в соответствии с `server/.env.example`.

1) Клонирование
```bash 
git clone git@github.com:DimitryAn/Mini-collector.git && cd Mini-collector
```
2) Запуск из корня проекта
```bash
docker compose --env-file ./server/.env up --build
```
